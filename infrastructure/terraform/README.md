# EPOS — AWS deployment (mid-development)

Single EC2 instance running the existing Docker Compose stack, fronted by Caddy
for TLS. Chosen over ECS/Fargate deliberately: the compose stack already works,
Eureka keeps functioning unchanged, and the whole thing costs ~$30/month instead
of ~$120.

```
Internet
   │  :80 (ACME challenge + redirect)  :443
   ▼
┌──────────────────────────────── EC2 t3.medium ────────────────────────────────┐
│  web (Caddy)  ── /            → Angular SPA (baked into the image)            │
│               ── /api/v1/*    → api-gateway:8080                              │
│               ── /ws*         → scoring-service:8083  (STOMP/SockJS)          │
│               ── /actuator/health → api-gateway:8080  (mobile connectivity)   │
│                                                                               │
│  api-gateway ─ discovery-server ─ auth ─ exam ─ scoring ─ postgres            │
│  (all internal, on the epos-network bridge — no host ports)                   │
└───────────────────────────────────────────────────────────────────────────────┘
```

## Prerequisites

- AWS credentials configured (`aws sts get-caller-identity` must succeed)
- Terraform ≥ 1.9

## First deploy

```bash
cd infrastructure/terraform
terraform init
terraform apply

cd ../..
./scripts/deploy.sh
```

`terraform apply` builds the infrastructure and bootstraps the instance;
`deploy.sh` ships the code and builds the images. The first build pulls the
whole Maven and npm dependency tree, so budget 10–15 minutes.

## Redeploying after a code change

```bash
./scripts/deploy.sh
```

It ships your **working tree**, including uncommitted and untracked files, so
you do not have to push to GitHub to see a change live.

## Why sslip.io

Caddy needs a real DNS name to obtain a Let's Encrypt certificate. `sslip.io`
resolves any hostname containing an embedded IP back to that IP, so
`epos.13-38-1-2.sslip.io` points at the Elastic IP with no domain purchase.
Real, browser-trusted HTTPS — which the Angular PWA service worker requires and
which keeps Android's cleartext-traffic block off Feten's back.

To move to a real domain later: point an A record at the Elastic IP and set
`EPOS_DOMAIN` in `/opt/epos/epos.env` to it, then redeploy. Nothing else changes.

## Pointing the mobile app at this deployment

`epos_mobile` reads its base URLs from `--dart-define` (see
`lib/core/constants/api_constants.dart`), so no code change is needed:

```bash
terraform output -raw mobile_dart_defines
```

## Secrets

`JWT_SECRET` and the Postgres password are generated by Terraform and stored as
SSM SecureStrings; the instance pulls them at boot through its IAM role into
`/opt/epos/epos.env` (mode 600). They are **not** placed in user_data, which is
readable via the instance metadata service.

`AI_READER_PASSWORD` / `AI_WRITER_PASSWORD` (the internal Postgres roles used
by `ai-service`) are generated by user_data itself with `openssl rand` and
written to the same file: they never leave the bridge network, and
`init-db/init2-ai.sh` reads them once, on the instance's first boot.

The JWT secret is 64 bytes, which makes `HmacJwtDecoders.autoSelectByLength`
select HS512 consistently in the signer (auth-service) and all three verifiers.
Both generated secrets are alphanumeric on purpose: a literal `$` would be
swallowed by compose's env interpolation.

`terraform.tfstate` contains these values in plaintext and is gitignored. It is
local-only state — do not commit it, and note that a lost state file means a
lost record of the deployment.

## ⚠️ Known exposure: seeded demo credentials

`infrastructure/init-db/init.sql` seeds well-known accounts
(`admin@epos.tn / Admin@1234` and friends). On a public URL these are trivially
guessable by anyone who finds the host. Acceptable for a development deployment
holding no real data; **change them before putting any real exam data in**, and
before circulating the URL beyond the team.

## Access

```bash
terraform output -raw ssh_command        # SSH (locked to your current public IP)
aws ssm start-session --target <id>      # Session Manager, works from anywhere
```

SSH is restricted to the public IP of whoever ran `terraform apply`. If your IP
changes, re-run `terraform apply` or set `ssh_allowed_cidr`.

## Operating

```bash
cd /opt/epos/app/infrastructure
C="docker compose --env-file /opt/epos/epos.env -f docker-compose.prod.yml"
$C ps
$C logs -f auth-service
$C restart exam-service
```

## Cost — read this, credits are finite

The account is on AWS's **Free plan** (`aws freetier get-account-plan-state`),
which carries a fixed credit balance rather than unlimited free usage, and
**refuses to launch any instance type outside the free-tier-eligible list** —
`t3.medium` fails with `InvalidParameterCombination`. Hence the
`c7i-flex.large` default.

Running 24/7, `c7i-flex.large` costs roughly **$55/month** (~$0.076/h) plus
30 GB gp3 (~$2.75). Against a $100 credit balance that is under two months, so
**stop the instance whenever you are not demoing**. The Elastic IP is retained
while stopped, so the URL and certificate stay valid:

```bash
aws ec2 stop-instances  --instance-ids $(terraform output -raw instance_id)
aws ec2 start-instances --instance-ids $(terraform output -raw instance_id)
```

Stopped, you pay only for storage (~$3/month) and the idle Elastic IP
(~$3.60/month). Check remaining credits with:

```bash
aws freetier get-account-plan-state --region us-east-1
```

```bash
aws ec2 stop-instances  --instance-ids $(terraform output -raw instance_id)
aws ec2 start-instances --instance-ids $(terraform output -raw instance_id)
```

## Teardown

```bash
terraform destroy
```

Destroys everything including the Postgres volume. Dump anything you care about
first.
